Download a new model
  1. Enter a model: an ollama name (e.g. qwen3:4b) or a HuggingFace GGUF repo or URL (e.g. https://huggingface.co/ggml-org/gemma-4-E4B-it-GGUF).
  2. For a HuggingFace model, set the quantization (Q4_K_M is a good, small default).
  3. Click Download. Progress shows below; the model appears in “Installed models” when it finishes.
Where to find model names
• ollama.com/library — browse and copy the name + tag exactly (e.g. qwen3:4b, gemma4:e4b-it-q4_K_M). Best supported on this backend.
• HuggingFace GGUF models — open a repo that contains GGUF files and paste its URL above.
• After it downloads, click Test in the list below to confirm the model actually loads and runs on this server.
Examples (click to fill):
qwen3:4b llama3.2:1b https://huggingface.co/ggml-org/gemma-4-E4B-it-GGUF https://huggingface.co/unsloth/gemma-4-E4B-it-GGUF
Note: HuggingFace repos must contain GGUF files. The original google/… repos are safetensors and won't work — use a community GGUF build (ggml-org, unsloth, bartowski). Downloads keep running on the server even if you close this page; reopen this tab to see progress again. Smaller quants (Q4_K_M) are safest on consumer GPUs.

Authentication (optional)

Authentication is off by default — anyone who can reach the server can use it. It's turned on on the server, not from this page (the browser can only supply the key, not set it).

To require a key:
  1. On the server, set API_KEY in the .env file (or as an environment variable) — e.g. API_KEY=choose-a-secret.
  2. Restart the server (./run.sh).
  3. Every request now needs that key. Paste the same value into API key above; it's sent as Authorization: Bearer <key> and remembered here.

/health and this page (/ui) stay open so the app can still load; every data endpoint returns 401 without a valid key. To turn auth back off, clear API_KEY and restart.
